# 个股详情图表迁移方案：TradingView Lightweight Charts

状态：已实施详情图表迁移、布局调整并完成下述回归。核对日期：2026-11-05。

- 基线：`4bd816e5`（已合并本地 `main`，未推送）。
- 工作分支：`codex/stock-detail-lightweight-charts`。
- 用户已确认：保留现有工具栏与操作，仅替换图表引擎；覆盖日 K、单日分时、多日分时。
- 方案级别：L3，直接调整现有图表渲染层。`stock-preview.footer` 只能扩展详情底部，无法替换核心画布，不为本次迁移新增插槽或通用图表注册平台。

## 1. 目标与边界

详情继续承担“查看价格和指标、对照历史分时、设置价格提醒”的任务。弹窗结构、工具栏、快捷切股、日期范围、自选与监控操作、扩展信息条沿用现有交互。

范围是 `StockPreviewDialogContent` 中的日 K、右侧历史单日分时、分时标签下的多日分时，以及这些详情弹窗的全屏状态。自选、策略、看板中打开的同一详情组件一起生效。

本轮不整体替换列表迷你图、指数页和独立分析/回测页面中的图表，不删除项目的 ECharts 依赖。共享组件增加最小的内部渲染器选择参数，旧调用方默认保持现有渲染器，详情入口明确选择新实现。该参数用于迁移隔离和测试，不增加用户设置项。

## 2. 库选择与当前情况

选择 **TradingView Lightweight Charts**。它是适配自有数据与界面的开源渲染库；完整工具栏、指标计算、画线工具不是自动随库提供的。Advanced Charts 属于另外的授权产品，本次不接入。数据继续来自 TSP 的 `/api`，不接 TradingView 行情，不新增 TradingView 账号或 Key 要求。参考：[官方产品比较](https://tradingview.github.io/lightweight-charts/docs/product-comparison)。

实施前 `package.json` 声明 `^4.2.0`，锁文件版本为 **4.2.3**。已有 `CandlestickChart.tsx` 只实现基础 K 线和成交量，源码搜索未发现业务调用，不能直接代替详情。板块成分弹窗也使用该库，须同步适配系列创建 API。

已锁定 **5.2.1**，利用原生多面板能力，避免用多个独立画布手动同步副图。[官方发布记录](https://github.com/tradingview/lightweight-charts/releases)、[多面板说明](https://tradingview.github.io/lightweight-charts/tutorials/how_to/panes)。

升级必须同时处理已有基础组件的 v4 调用，避免未使用组件仍令全量 TypeScript 编译失败；保留它的导出与基本行为。系列创建和标记 API 按官方迁移文档适配。[v4 → v5 迁移说明](https://tradingview.github.io/lightweight-charts/docs/migrations/from-v4-to-v5)。

## 3. 调用链与改动位置

现有调用链：

```text
StockPreviewDialogContent
  ├─ StockPanel
  │   ├─ StockInfoBar
  │   ├─ StockDailyKChart → EChartsCandlestick
  │   └─ StockIntradayChart → EChartsIntraday
  └─ StockMultiDayIntradayChart → EChartsMultiDayIntraday
```

保留查询和业务组件，只将最右侧的绘制实现替换为新的渲染器：

| 位置 | 处理方式 |
| --- | --- |
| `StockPreviewDialogContent.tsx` | 指定详情使用新引擎，保留顶部操作与弹窗状态 |
| `StockPanel.tsx` | 透传内部渲染器参数，保留日期选择、价格联动和邻股预取 |
| `StockDailyKChart.tsx` | 保留查询、指标开关、数据转换和标记生成，选择对应画布 |
| `StockIntradayChart.tsx` | 保留查询、补齐、空态、历史日期与显示设置，替换单日画布 |
| `StockMultiDayIntradayChart.tsx` | 保留历史/实时合并、补齐及缓存失效，替换多日画布 |
| `EChartsCandlestick.tsx` 的类型和指标定义 | 抽离与引擎无关的类型、元数据及已有计算函数；旧路径可重导出，兼容现有导入 |
| `CandlestickChart.tsx`、`DimensionMembersDialogContent.tsx`、包与锁文件 | 适配 v5 系列创建 API，保留旧消费者 |

已新增 `charts/LightweightDaily.tsx`、`charts/LightweightIntraday.tsx`、`charts/FinancialPlot.tsx`、`charts/ChartAnnotations.ts` 和 `lib/lightweight-model.ts`。单日和多日分时共用序列适配逻辑，保留各自业务外壳。

现有 `SubChartDef.buildSeries` 返回 ECharts 配置，不能直接传给 Lightweight Charts。先分离指标含义、配置和数据计算，再由不同渲染器生成自己的图元，避免复制两套指标公式。

## 4. 功能保留矩阵

| 现有能力 | 新实现方向与验收点 |
| --- | --- |
| 日 K、MA5/10/20/60、BOLL | 蜡烛及折线系列；数据值、颜色和显隐与原图一致 |
| 成交量、MACD、RSI、KDJ | v5 原生 panes；同一日 K 实例内共享时间轴、缩放和十字线 |
| 量比、前 N 日均量、量柱标签 | 复用现有计算与配置；均线和必要标签单独适配，不能只迁移量柱 |
| 买卖、涨停/炸板、异动标记 | 买卖点沿用 series markers；异动提供文字标签、颜色柱体两种样式。涨停黄柱，炸板阳线玫紫、阴线或开收同价蓝紫；缩小后文字标签收成小圆点 |
| 自选日期、区间背景、有限日期范围的价格线 | 定制 primitive；正确裁剪到可见区间，随缩放和尺寸变化同步 |
| 监控价格线、跨图价格联动 | 价格线与坐标转换；保留当前价格回调和价格口径 |
| 点击日 K 查看指定日期分时 | 从图表时间映射回原始日期，沿用 `onDateClick` 链路 |
| 双击图表设置价格提醒 | 只响应价格主面板；副图、价格轴缩放及拖动不误触发 |
| 单日分时、均价、成交量、昨收与涨跌幅 | 复用 `intraday-chart.ts` 的计算、单位和格式化，保持当前空值含义 |
| 自适应/涨跌停显示 | 按已有 `PriceLimitInfo` 与资产类型处理；不为 ETF、指数或无涨跌幅标的强画股票涨跌停带 |
| 多日分时 | 每个交易日独立分段、均价每日重置、保留日期分隔，不跨日连接成一条价格线 |
| 信息栏、扩展字段、财务数据 | 继续由既有组件与接口提供，图表库不重算业务数据 |
| 快捷切股、全屏、主题、日期范围 | 保持旧操作和存储键；刷新数据保留用户视口，切股清除旧标的交互上下文 |

基础标记与价格线可使用官方 API；区间背景、日期竖线及有限长度线段需要适配，不能把 ECharts 的 `markArea/markLine` 直接搬过去。[标记说明](https://tradingview.github.io/lightweight-charts/tutorials/how_to/series-markers)、[图元扩展说明](https://tradingview.github.io/lightweight-charts/docs/plugins/intro)。

## 5. 时间和数据契约

1. 日 K 使用业务日期，不经浏览器本地时区换日；图表选择结果映射回同一原始日期。
2. 分钟数据仍遵守后端的北京时间墙钟契约。适配器显式拆分年月日时分，构造仅供画布使用的时间键；不使用依赖宿主时区的字符串 `Date` 解析，不把画布时间键回传为后端业务时间。
3. 刻度和悬浮信息使用同一时间映射，在 UTC、北京时间和美洲时区浏览器中均显示原始北京时刻。Lightweight Charts 自身没有内置业务时区处理，必须由适配层保证。[官方时区说明](https://tradingview.github.io/lightweight-charts/docs/time-zones)。
4. 分时绘图基于 `FULL_DAY_TIMES`，仅在新渲染器内将 `11:30/13:00` 合为同一午间位置，每日 241 个画布位置；全局 242 个源时间与原始数据保持不变。未到达的下午时段使用空白点保留位置；真实缺失价格、开盘价或成交额不补零，不跨实际缺口伪造连续走势。两个午间边界都有记录时保留各自价格和均价端点，共用一根量柱，悬停明确标注“午间衔接”。
5. 多日分时保留真实日期和分日边界，不能把各日的 `09:30` 合并成同一个时间点。继续遵循数据源历史深度限制，只提供当前支持的周期。
6. 排序、去重、空值、NaN、数值精度和量额单位在纯适配函数中验证。均价仍复用既有实现，不另算一份金融公式。

## 6. 缓存、更新与性能

- 保留现有 API、TanStack Query 键、邻股预取、SSE、补齐任务及跨窗口数据版本校准。渲染器只接收数据，不自行请求上游、创建轮询或启动后台任务。
- 同一标的实时尾部更新优先用系列增量更新；历史修补、数据范围变化或切股时再设置完整序列。
- 日K实时更新保留用户缩放和浏览范围；分时按所选完整时段固定展示，在数据或画布尺寸变化时重新适配。切换标的后不能残留上一标的的标记、悬停数据或日期。
- 图表实例在挂载时创建、卸载时销毁；统一清理事件订阅、ResizeObserver 和 requestAnimationFrame。隐藏弹窗不保留活动实例。
- 十字线信息更新限制在图表局部，避免鼠标移动驱动整个详情重新渲染。
- 抽离运行时依赖，避免新渲染器因导入 ECharts 常量而额外加载整套旧引擎。旧引擎继续按其他页面的使用需要保留。
- 用相同机器、数据和视口记录迁移前后的首屏耗时、实时更新耗时、交互帧、内存趋势、请求次数和构建 chunk。暂不宣称固定比例的性能提升。

## 9. 兼容与归属

后端数据、数据源配置、Key、Parquet、指标口径、旧设置键和资源包不迁移。新图表继续读取旧数据与旧偏好，归属链接与第三方声明随本地依赖交付；不额外引入外部 CDN 脚本。

详情画布隐藏重复的 TradingView 角标，署名及 TradingView 链接集中在「设置 → 关于 → 版权」展示，弹窗底部不再重复展示；相应 LICENSE/NOTICE 仍随应用分发并可从关于页查看。官方要求用户可访问页面保留署名和链接，并未要求固定放在图表旁；`attributionLogo` 可在已满足链接要求时关闭。[官方归属说明](https://tradingview.github.io/lightweight-charts/docs#license-and-attribution)、[角标选项](https://tradingview.github.io/lightweight-charts/docs/api/interfaces/LayoutOptions#attributionlogo)。

## 11. 双轴及柱体比例调整（当前方案）
