# 持仓分析 pi-agent 实现规范（Position Analysis Agent Spec）

> 来源：8-26 ~ 8-31 五个交易日实盘盯盘会话的逻辑沉淀（fm/engine 会话，2026-08-31）。
> 目标：在 tickflow-stock-panel AI 模块实现一个独立 pi-agent，复现该会话中的持仓分析能力。
> 本文档定义"要实现的逻辑"，不定义代码结构——请对接本仓库现有 AI 模块架构自行落地。

## 1. Agent 定位

- **输入**：持仓快照（数量/成本）、实时行情、分钟级大单资金流、日线技术指标、可选新闻/情绪流
- **输出**：**纪律化判定**（判定表 + 动作建议），不是预测、不是荐股
- **核心价值**：把"人肉盯盘时的分析逻辑"代码化——每 5/10 分钟一轮，产出一致的、可推送的判定

## 2. 数据接口需求（按优先级）

| 优先级 | 数据 | 来源参考 | 关键口径 |
|---|---|---|---|
| P0 | 持仓快照 | fhold-cli `position list --format json` | quantity/cost_price/position_ratio；**每日开盘前刷新**，盘中不重取 |
| P0 | 实时价 | fm-cli `realtime quote --code X` | 现价/开/高/低；注意**快照有秒级延迟**，四票串行拉取时各票时间戳不同 |
| P0 | 昨收基准 | 日K库（如 tdx.duckdb market_day_kline）| **必须每日从日K自动取，严禁硬编码**（跨日复用会产出全错的涨跌幅——8-31 实际事故） |
| P1 | 分钟大单资金 | live moneyflow store（super_large_net+large_net） | 见 §4 口径声明 |
| P1 | 日线 MA 系统 | 日K库 MA5/MA10/MA20 | 技术位判定基线 |
| P2 | 板块资金流 | fm-cli `moneyflow minute -t 40` | 板块定性用 |
| P2 | 新闻/情绪 | 股吧/搜索 | 仅作情绪加权项，见 §6 |

## 3. 核心分析逻辑（每轮执行的判定管线）

### 3.1 仓位瀑布（先算账再判定）

```
for each 持仓票:
  持仓盈亏 = quantity × (现价 − cost_price)
  今日盈亏 = quantity × (现价 − 昨收)
  涨幅 = 现价/昨收 − 1
合计今日 = Σ今日盈亏; 若 < −3000 元 → 输出附加警示
机械校验: |现价/昨收 − 1| > 15% → 数据异常报警，本轮判定作废
```

### 3.2 纪律位检查（三级标注，强制格式）

- **L1 既定**：价格触发**无条件执行**的线（如止损、既定减仓区）。输出格式：`L1: 触发线 X，现价 Y，距离 Z%`
- **L2 新设待确认**：临场新设的风控条件，**必须用户点头且注明"新设"**，agent 只能建议不能判定执行
- **观察**：不定性、不动作，仅播报状态

### 3.3 资金面分析（关键方法论）

- **分段斜率 > 绝对累计**：大单累计会随时间自然增大，判定要用"最近 N 桶的净额斜率"（如 30 分钟净流出 >0.5 亿 = 加速派发）
- **当日口径可比性**：数据源若盘中重启/断档，恢复后的"今日累计"与全天口径不可比——判定改用"时段净额"而非累计
- **尾盘特殊窗口**：指数调仓日（MSCI 等）尾盘 14:55-15:00 有被动盘，该窗口读数不用于触发纪律
- **交叉核对**（低频，每日一次）：live 桶 total_amount 累加 vs 行情实际成交额。偏差 ≪1.0x = 缺桶少采（读数保守但方向可信）；>1.2x = 重复计数（全票大单数字作废，回退纯价格判定）

### 3.4 情景框架输出（不是预测，是条件分支）

每轮输出主判定票的三情景 + 主观概率 + 各自触发位：

```
| 情景 | 概率 | 触发位 → 动作 |
|---|---|---|
| A 弱势 | 55% | 破 X → 阶梯减仓(L1) |
| B 修复 | 30% | 收复 Y → 减仓窗口(L1减仓区) |
| C 强攻 | 15% | 需大单转正配合 |
```

约束：历史样本 ≤3 次只能作情景框架**不能推规律**；概率是主观估计，需标注"非投资建议"。

### 3.5 判定先行原则（输出顺序铁律）

每轮输出顺序固定：**① 判定表 → ② 关键变化文字 → ③ 待用户裁决项**。工具调用/数据采集永远不放在判定文字之前。

## 4. 数据源已知坑（必须内建容错）

1. **fetcher 停摆**：live store 采集进程会静默停摆（跨日高发、重启后 27min~3h 不定再次停摆）。每轮先验 `records[-1].bucket_time` 与当前时间差 >15 分钟 → 大单列标注"冻结至 HH:MM"，判定降级为纯价格
2. **重启回补口径漂移**：采集重启后回补时段与原桶可能有出入 → 盘中轮的大单累计仅供参考，**收盘后用物化终值（EOD 落库）做正式复核**
3. **中小单字段恒 0**：该数据源只有主力口径（超大+大单），"散户方向不可判"——**禁止**输出"散户抢筹/散单对撞"类结论
4. **跨日基准**：昨收必须动态获取（见 §2 P0）
5. **分钟桶盲区**：采集断档段的资金结构缺失时，价格结论可以照常出（行情接口独立），**资金归因必须标注"盲区推断"**

## 5. 输出格式（推送模板）

```
**{HH:MM}轮 · {date}持仓盯盘**[ ⚠️警示]

| 票 | 现价 | 涨幅 | 持仓盈亏 | 今日 | 大单 |
|---|---|---|---|---|---|
(每票一行，来自 §3.1)

今日合计: N元

纪律: (每票既定线列表)
```

变化超出噪声时追加"关键变化"段；L2 类裁决项单独成段，格式：`L2 双条件状态：价格腿 ✓/✗（现价 vs 线）、资金腿 ✓/✗（口径声明）→ 待用户裁决（执行含义 = 卖 N 股）`。

推送通道：`meow send --type markdown --title "盯盘 {HH:MM}" --stdin`（可选配置）。

## 6. 证据分级（信息使用红线）

| 级别 | 来源 | 使用规则 |
|---|---|---|
| A 已核验 | 公告/财报/官方指数数据 | 可作决策依据；引用时给来源 |
| B 行情数据 | 实时价/日K/大单 | 主判定依据；标注数据截止时间 |
| C 传言级 | 股吧/自媒体数字 | **只能作情绪加权项，不得进入决策依据**；标注"未核验" |
| D 推断 | agent 自己的推理 | 标注"[INFERENCE]"，与事实分开 |

## 7. 会话实测案例（供回归测试用例设计）

1. **跨日基准事故**：昨收硬编码 8-27 收盘，8-31 复用导致烽火 +2.5% 误报为 −0.4%、合计 −4,363 误报（真值 −1,670 早期口径）→ 测试：跨日后涨幅与今日盈亏必须正确
2. **L2 悬置→消解**：价格腿盘中破 104（成立）→ 收盘收回 104.75（消解）→ agent 须在收盘口径翻转判定，而非沿用盘中状态
3. **分段斜率修正**：午前把"含上午的累计 −2.42 亿"误当午后流出（斜率高估 2.7 倍）→ 测试：时段净额与累计净额必须分开字段
4. **交叉核对**：live 桶额/实际成交额 = 0.83~0.91x（缺桶）→ 测试：偏差检测阈值与降级逻辑
5. **长鑫换手日**：开盘 +12.5 亿扫货 → 全天对倒至 +4.6 亿 → 尾盘竞价压价——判定应输出"利好兑现换手"而非"洗盘/出货"二选一

## 8. 明确不做的事

- 不做股价预测（只做条件→动作映射）
- 不自动执行任何交易动作（L1 也只输出"触发"信号，执行是人）
- 不用盘中单点数据推翻收盘口径的既定判定
- 不在数据断档时伪造资金读数（宁标 n/a）
