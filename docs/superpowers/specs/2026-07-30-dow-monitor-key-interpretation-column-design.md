# 趋势监控重点解读列设计

## 目标

在 `/dow-monitor` 保留全部原始指标的前提下，新增一列可快速扫读的“重点解读”，
把趋势、动量、量价、资金、盘口和风险压缩成固定三行，帮助用户在每页 20 只股票中
快速找到值得进一步查看的股票。

稳定需求 ID：`REQ-DOW-MONITOR-KEY-INTERPRETATION-COLUMN-001`。

重点解读是对页面现有证据的确定性摘要，不生成、清除、翻转或升级正式买卖信号。

## 已批准方案

采用方案 A：

- 保留当前全部指标列；
- 新增“重点解读”列；
- 列位于“日内走势”之后、“趋势 / 位置”之前；
- 每行固定显示三行摘要；
- 本轮不提供精简模式，也不折叠原始指标。

把新列放在详细指标之前，使用户不需要横向滚动到表格末端即可先读摘要，再按需核对
右侧原始证据和正式信号。

## 三行摘要结构

每只股票最多显示三行，每行最多选择两个短语：

1. **状态行**：通道方向与多周期动量；
2. **证据行**：量速、相对量能、资金流入或五档盘口中最有辨识度的证据；
3. **风险行**：突发异动、接近日高/日低、ATR 风险、周期分歧或数据时效问题。

示例：

```text
上升通道 · 动量同向上
量速 2.4× · 资金流入 61%
异动：盘口 +72% · 距日高 0.3%
```

下降或矛盾场景示例：

```text
下降通道 · 动量同向下
卖盘占优 -58% · 量能 1.8×
接近日低 0.4% · 波动偏高
```

```text
震荡/过渡 · 周期分歧
量能一般 · 资金待确认
等待稳定周期确认
```

摘要不用完整句，数字保留与原始列相同的单位和精度。无法可靠解释的字段显示
“数据不足”或“待确认”，不得补零或推测。

## 选择与优先级规则

摘要由纯前端确定性函数根据 `deriveMonitorRow` 的现有展示结果生成，不调用大模型，
不增加后端接口。

### 状态行

第一短语固定使用通道：

- `UP`：上升通道；
- `DOWN`：下降通道；
- `RANGE`：震荡/过渡；
- `PENDING`：通道待确认；
- `UNKNOWN`：通道数据不足。

第二短语按 1m、5m、15m 动量选择：

- 三个有效周期同向上涨：动量同向上；
- 三个有效周期同向下跌：动量同向下；
- 1m 与 5m/15m 明显不同：短线转强、短线转弱或周期分歧；
- 有效周期不足：动量待确认。

“转强/转弱”只描述 1m 与稳定周期的相对方向，不表示正式买卖信号。

### 证据行

从以下证据中按顺序选择最多两项，跳过缺失或延迟值：

1. 当前仍在 10 秒窗口内的量速或盘口异动；
2. 1m 量速；
3. 稳定相对量能；
4. 资金流入占比；
5. 五档盘口压力。

异动证据显示当前值，例如“量速异动 3.2×”“盘口异动 -65%”，不推断挂单一定成交。
若没有足够证据，显示“量价待确认”。

### 风险行

按以下顺序选择最多两项：

1. 当前仍在 10 秒窗口内的涨跌幅、1m 涨速、距日高或距日低异动；
2. 对应数据源延迟或缺失；
3. 距日高或距日低更近的一侧；
4. 既有 `riskTitle`；
5. ATR14 或振幅/ATR 明显偏高；
6. 15m、30m 周期确认不足。

如果前两行已经展示同一指标，风险行不重复该证据。没有明确风险时显示
“暂无突出风险”，而不是给出操作建议。

同时发生多个异动时，固定使用以下顺序，避免文本随渲染顺序跳动：

1. 涨跌幅；
2. 1m 涨速；
3. 1m 量速；
4. 五档盘口；
5. 距日高；
6. 距日低。

## 稳定性与刷新

- 摘要跟随现有 WebSocket 和 HTTP 回退数据更新，不新增轮询；
- 只有摘要短语或格式化数值发生变化时才改变文本；
- 10 秒异动标记到期后，摘要回到常规证据；
- 股票离开当前页后不保留摘要状态；
- 不为了稳定显示而缓存过期行情；
- 数据延迟时优先显示时效问题，不继续展示已经失效的实时判断。

## 视觉设计

- 表头：`重点解读`；
- 列宽约 260px，设置稳定的最小宽度，不允许挤压成逐字换行；
- 三行使用与现有组合指标相近的紧凑行距，不额外提高现有表格行高；
- 第一行使用较高文字权重，第二行使用普通前景色，第三行使用弱化文字；
- 只有正在发生的突发异动和明确风险短语使用红色；
- 不给整格或整行铺红色背景；
- 摘要中的“异动”保留文字提示，红色不是唯一识别方式；
- 单元格提供包含三行完整内容的可访问名称，截断时仍可通过 `title` 查看完整文本。

上升、下降和震荡保持现有页面的颜色语义，不引入一套与正式信号冲突的新颜色系统。

## 正式信号边界

重点解读不得使用“建议买入”“建议卖出”“立即操作”“止盈”或“止损”等指令性
文案。它不得：

- 读取正式信号后自行改变摘要方向；
- 把实时指标升级为正式信号；
- 修改正式信号标签、时间、来源或排序；
- 修改完成分钟决策、通知或持久化记录；
- 修改 3018 后端、19912 道氏引擎或 WebSocket 订阅。

“买卖信号”列仍是唯一正式信号展示。重点解读只回答“现在的盘面证据是什么”，
不回答“用户必须执行什么操作”。

## 组件与数据流

新增独立的纯展示函数，输入为：

- 当前行 `MonitorRowPresentation`；
- 当前股票的突发异动键集合；
- 已有数据时效状态。

输出为三个结构化行对象，每行包含：

- 可见短语；
- 语义级别：普通、弱化、异动或风险；
- 完整可访问文本。

`DowMonitorList` 只负责把这三个结构化行渲染到新增单元格。优先级、缺失处理和文案
不能直接散落在表格 JSX 中。

这种边界使摘要语义可独立测试，并避免未来修改文案时破坏列表选择、分页、详情开合
或正式信号。

## 帮助页

`/dow-monitor/help` 增加“重点解读”说明，解释：

- 三行分别回答什么问题；
- 异动和风险为何显示红色；
- “数据不足”“待确认”“周期分歧”的含义；
- 摘要不等于买卖建议；
- 用户可在右侧原始指标中核对摘要依据。

## 测试策略

遵循测试先行：

1. 纯摘要函数测试先证明通道和三周期动量组合能生成正确状态行；
2. 测试证据选择、最多两项、固定优先级和不重复规则；
3. 测试异动、延迟、缺失、周期分歧与风险选择；
4. 测试任何输入都不会生成指令性买卖文案；
5. 组件测试证明新列位于日内走势之后、趋势 / 位置之前，且固定显示三行；
6. 组件测试证明异动只突出对应短语，不给整格或整行染色；
7. 回归测试证明买卖信号、信号时间、分页、详情开合和现有全部指标仍保持不变；
8. 帮助页测试证明摘要结构和正式信号边界可被用户找到。

截图和快照只能作为视觉辅助，不能替代摘要优先级、缺失语义和正式信号边界的行为
测试。

## 性能边界

- 当前页最多 20 只股票，每次只对现有派生展示值做常数级短语选择；
- 不增加 API 请求、WebSocket 订阅、定时器或持久化；
- 使用纯函数和已有 memo 化边界，避免为每个摘要创建独立状态；
- 摘要不得触发列表排序或自动滚动。

## 非目标

- 不删除、隐藏或折叠任何原始指标列；
- 不提供精简/完整模式切换；
- 不增加新的买卖信号或评分；
- 不调用大模型生成实时解读；
- 不保存摘要历史；
- 不根据摘要自动排序、通知或交易；
- 不在本轮提供文案、阈值或优先级自定义。

## 验收标准

1. 列表在“日内走势”和“趋势 / 位置”之间显示宽度稳定的“重点解读”列；
2. 每只股票固定显示状态、证据、风险三行，且每行最多两个短语；
3. 摘要优先展示有效异动和关键风险，缺失或延迟时明确说明，不补零；
4. 异动和风险仅突出对应短语，整行、整格及正式信号样式不受影响；
5. 任意摘要变化都不改变正式买卖信号、信号时间、后端决策或 WebSocket；
6. 当前全部原始指标、分页、20 只每页和详情开合继续正常；
7. 帮助页说明摘要阅读方法和非买卖建议边界。
