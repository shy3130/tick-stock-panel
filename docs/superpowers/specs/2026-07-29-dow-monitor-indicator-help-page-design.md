# 趋势监控指标帮助页设计

日期：2026-07-29

状态：待用户书面规格确认

## 1. 目标

为 `/dow-monitor` 增加一个独立、结构清楚的指标帮助页，使用户不用离开当前产品就能理解列表中的四组指标、`实时`/`稳`标识、组合判断方法和正式信号边界。

帮助页解决“指标是什么、数值高低怎么看、应该和什么一起看、哪些结论不能从单个指标得出”四个问题，不提供自动下单，不新增前端买卖信号，也不改变任何行情、分析或通知数据。

## 2. 已确认的入口和路由

采用独立页面方案：

- 在趋势监控页顶部的 `PageHeader` 操作区增加带帮助图标的“指标说明”链接；
- 链接进入 `/dow-monitor/help?market=<当前市场>`；
- 帮助页顶部提供“返回趋势监控”，返回 `/dow-monitor?market=<原市场>`；
- `market` 只接受 `cn`、`hk`、`us`，缺失或非法时回退到 `hk`；
- 不在全局侧边栏增加新的一级菜单，避免帮助内容与日常盯盘入口并列。

帮助页使用现有 `Layout`，通过前端路由懒加载，不请求新的后端接口。

## 3. 信息架构

### 3.1 页面标题区

标题为“趋势监控指标说明”，副标题说明：

> 先看正式信号，再用趋势、动能、量价和风险判断信号质量与执行风险。

标题区包含：

- 返回趋势监控；
- 当前市场提示；
- `实时`与`稳`两种标签的简短图例；
- “指标是辅助判断，不构成收益保证”的边界说明。

### 3.2 快速决策路径

页面首屏展示四步阅读顺序：

1. 看“买卖信号”：确认后端是否已有正式方向和时间；
2. 看“趋势 / 位置”：判断方向和价格所处位置；
3. 看“动能 / 涨速”与“量价 / 资金”：判断短线是否同向、是否有成交与盘口配合；
4. 看“突破 / 风险”：判断距离关键位置有多远、波动风险和稳定周期是否确认。

该顺序只解释阅读方法，不在前端重新计算或覆盖正式信号。

### 3.3 四组指标说明

四组使用统一卡片结构，每张卡固定包含：

- 这组回答什么问题；
- 指标名称与页面显示示例；
- 数据来源和更新类型；
- 数值增大/减小表示什么；
- 应该和哪些指标一起看；
- 常见误读。

#### 趋势 / 位置

解释：

- 通道：`上升通道`、`下降通道`、`震荡/过渡`、`待确认`；
- 控制：价格相对稳定控制线的百分比距离，稳定数据按 15m → 30m → 缺失回退，永不使用 5m；
- 成本：价格相对当日平均成交成本（VWAP）的偏离。

必须明确：

- 通道描述方向，不等于可立即买卖；
- 控制和成本的正负必须结合正式信号及通道理解；
- `--`表示没有满足稳定数据条件，不表示 0%。

#### 动能 / 涨速

解释：

- `1m`：当前分钟开盘到现价的变化，带 `实时`；
- `5m`、`15m`：最近两根完成 K 线收盘变化，属于稳定观察值。

必须明确：

- 1m 容易快速变化，只说明当前分钟加速方向；
- 5m 与 15m 同向时比单一 1m 更稳定；
- 实时 1m 不能生成、翻转或升级正式信号。

#### 量价 / 资金

解释：

- 量比：稳定周期当前成交量相对历史均量；
- 量速：当前 1m 成交量按分钟投影后，相对最近 12 根完成 5m K 线每分钟基准的倍数；
- 主买：完整资金数据中主动买入占比；
- 五档：买一至买五和卖一至卖五挂单量的压力差。

必须明确：

- 量比和主买带 `稳`，量速和五档带 `实时`；
- 五档是当前挂单结构，撤单会使其快速变化；
- 量价增强只能用于验证走势，不能单独视为买点。

#### 突破 / 风险

解释：

- 高：现价距离当日最高价的百分比，越接近 `0%`越靠近日内高点；
- 低：现价距离当日最低价的百分比，越接近 `0%`越靠近日内低点；
- ATR14：15m 最近 14 个有效真实波幅相对最新完成收盘价的百分比，只描述波动风险；
- 确认：15m、30m 两个稳定周期中的同向确认数量，只显示 `0/2`、`1/2`、`2/2`。

必须明确：

- 接近日高不等于必然突破，接近日低也不等于必然破位；
- ATR14 越大表示短线波动范围越大，不表示上涨或下跌；
- 确认数量表示稳定周期一致性，最终方向仍看正式买卖信号。

### 3.4 典型组合场景

帮助页提供四个不依赖具体阈值的示例：

1. 向上突破候选：靠近日高、动能向上、量价增强、正式信号为买入；
2. 向下破位风险：靠近日低、动能向下、卖盘或卖出资金增强、正式信号为卖出/风险；
3. 假突破警惕：靠近关键位置但量价不配合、稳定周期未确认；
4. 继续观察：位置不关键、动能分歧或关键字段缺失。

示例只能使用“关注、警惕、继续观察”等解释性文案，不得生成新的“买入确认”“卖出确认”。

### 3.5 指标速查表

页面末尾提供紧凑表格，列为：

- 指标；
- 更新类型；
- 越大通常表示；
- 越接近 0 通常表示；
- 缺失显示；
- 不能单独得出的结论。

表格在窄屏中允许自身横向滚动，不能造成文档整体横向溢出。

## 4. 视觉与交互

- 延续趋势监控的深色卡片、边框和语义色；
- `实时`使用现有青色标识，`稳`使用现有稳定标识样式；
- 四组卡片使用不同但克制的图标，不能靠颜色单独表达含义；
- 桌面端采用左侧粘性目录、右侧正文；移动端目录变为顶部横向锚点；
- 点击目录定位到对应分组，标题锚点可被键盘聚焦；
- 正文以短句、示例和“常见误区”提示为主，避免连续大段术语；
- 页面不使用行情假数据模拟实时跳动。

## 7. 测试与验收

### 7.1 可执行测试

先写失败测试，再实现：

1. 趋势监控顶部存在“指标说明”链接；
2. 当前市场为 `cn`、`hk`、`us` 时，帮助链接保留对应 `market`；
3. `/dow-monitor/help` 路由可直接打开；
4. 帮助页返回链接保留合法市场，非法参数回退 `hk`；
5. 四组标题、快速决策路径、典型场景和速查表完整存在；
6. `实时`/`稳`、`--`、`0/2`至`2/2`和正式信号边界说明存在；
7. 不出现把五档、ATR或距离直接表述为正式买卖信号的文案；
8. 构建和现有趋势监控测试保持通过。

### 7.2 语义验收

1. 从趋势监控页顶部进入帮助页并返回，市场筛选不丢失；
2. 桌面和移动视口均能按目录找到四组指标；
3. 速查表只在自身容器滚动，页面没有整体横向溢出；
4. 指标名称、公式含义、刷新类型和缺失规则逐项对照权威规格；
5. 帮助页不产生 API 请求、不创建 WebSocket 订阅、不改变正式信号；
6. 独立复核从每个需求 ID 追踪到实现、可执行测试和浏览器语义证据。

截图只能作为外观辅助证据，不能替代入口、路由、参数保留、内容准确性和可访问性验收。
