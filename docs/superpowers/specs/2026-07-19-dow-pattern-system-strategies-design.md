# 道式形态系统策略接入设计

## 背景与目标

将用户既有道式形态与买点方法接入 TickFlow 的“系统内置策略”，部署到
`192.168.10.28:3018`。每种方法以独立策略卡片出现，复用
`longbridge-stock` 中的共享检测核心，并保持筛选、监控和回测对信号语义的一致理解。

本次明确不接入：

- 道氏趋势线—买卖点
- 强弱结合

“十三个买点”不建立汇总卡片，只接入现有笔记中规则明确的四个核心买点。未知的其余
九类不推测、不占位。

## 范围

### 系统策略卡片

| 策略 | 角色 | 命中定义 |
|---|---|---|
| 头肩底结构 | 买点 | 放量突破颈线，或突破后回踩颈线站稳 |
| 头肩顶结构 | 风险 | 跌破颈线，或跌破后反抽颈线失败 |
| 普通三角型 | 买点 | 对称三角形上沿放量突破 |
| 直角三角型 | 买点 | 水平压力位放量突破 |
| 启明星 | 买点 | 三根K线完成底部反转确认 |
| 黄昏之星 | 风险 | 三根K线完成顶部反转确认 |
| 三个红小兵 | 买点 | 连续三根实体阳线，收盘价依次抬高 |
| 底部孕线 | 买点 | 小实体K线后出现放量大阳线，后一根最高价和最低价完全吞没前一根 |
| 顶部孕线 | 风险 | 小实体K线后出现放量大阴线，后一根最高价和最低价完全吞没前一根 |
| 2B结构 | 买点 | 完整五浪下跌后破低，下一根K线立即以大阳线收回 |
| 底部头肩右肩 | 提前买点 | 潜在右肩回踩约50%位置并获得量价确认 |
| 二次测试 | 买点 | 重要支撑再次测试后出现大阳线、长下影或反包 |
| 强势出现 | 买点 | 底部区域出现放量大阳线并突破短期压力 |

“孕线”沿用用户旧笔记定义。该定义在常见K线术语中更接近外包线或全区间吞没，
但系统中的名称仍保留“孕线”，并在卡片说明中明确写出判断条件。

现有“多市场结构突破”策略继续保留。普通三角型与直角三角型新增独立卡片，并分别只
启用对应检测器，不改变原组合策略的行为。

## 架构

采用“共享核心 + TickFlow 适配层 + 独立内置策略卡片”三层结构。

1. `longbridge-stock` 负责形态识别、因果状态推进、结构证据、确认时间和无未来数据保证。
2. TickFlow 共享适配层负责把 `MarketDataMatrix` 转为按股票排列的已完成日K，将核心检测
   结果映射为 `SignalMatrix`。
3. 每张内置策略卡片只声明元数据、参数、信号角色和所使用的检测器，不复制算法实现。

共享核心通过固定提交构建本地 wheel，存入 TickFlow 的 `backend/vendor/`，并在构建说明
中记录源分支、源提交、测试命令和 SHA-256。TickFlow 不直接导入其他工作区源目录。

## 信号方向与产品语义

现有 TickFlow 矩阵策略以 `entry` 作为筛选命中依据，这会把看空形态误解为买点。本次扩展
策略元数据，增加明确的策略角色与筛选信号方向：

- `buy`：以 entry 信号作为筛选命中，可用于筛选、监控和买入回测。
- `risk`：以 exit/risk 信号作为筛选命中，可用于筛选和监控，不允许作为买入回测策略。
- `early_buy`：仍使用 entry 信号，但卡片明确标注“提前买点”，与颈线确认后的头肩底区分。

后端是角色约束的权威来源。风险策略提交回测请求时返回明确的业务错误；前端同时隐藏或
禁用其买入回测入口，并展示红色“风险”标识。监控规则可选择相应的风险方向。

## 数据流

```text
Longbridge ClickHouse 日K
  -> TickFlow MarketDataMatrix
  -> 按股票提取有效且已完成的OHLCV序列
  -> longbridge-stock共享检测器
  -> 带known_at_index的形态事件
  -> 买点或风险SignalMatrix
  -> 筛选器 / 监控 / 合法的回测入口
```

所有形态必须使用 `known_at_index` 映射到联合交易日日历，禁止把局部数组下标直接当成全局
日期下标。信号只允许落在检测器当时已经看到的K线上。

## 策略规则与参数

复用已有检测器参数和已测试默认值。卡片只公开对使用者有直接意义的少量参数：

- 头肩结构：颈线容差、突破量能要求、回踩确认窗口。
- 三角型：最小突破量比，其他几何约束采用共享核心默认值。
- 启明星、黄昏之星、三个红小兵：最小实体比例。
- 底部/顶部孕线：前一根最大实体比例、后一根最小实体比例、最小放量倍数。
- 2B结构：五浪最大跨度、大阴线/大阳线最小实体比例、立即收回窗口固定为下一根K线。
- 底部头肩右肩：50%回撤容差和量能确认阈值。
- 二次测试：支撑接近容差、测试间隔、确认K线类型开关。
- 强势出现：底部区间窗口、底部位置阈值、最小实体比例、最小放量倍数。

参数归一化沿用 TickFlow 现有机制。非法参数由策略加载/执行边界返回可读错误，不在检测器
内部静默修正。

## 数据需求与性能

所有策略使用日K，支持股票资产。纯价格形态可继续支持现有三市场股票符号。

- 普通K线组合只请求必要窗口及少量量能均线预热。
- 头肩、2B、二次测试等结构策略最多请求520根日K。
- 每只股票独立运行检测器，避免一个股票的数据问题污染其他股票。
- 共享适配层统一完成矩阵到K线对象的转换，避免每张卡重复构造相同数据。

首版不增加分钟周期，不增加空头交易执行，不改变现有组合策略的默认参数。

## 容错

- 历史不足、OHLC非有限值或必要成交量缺失：该股票返回不命中。
- 单只股票检测失败：记录股票和策略上下文，隔离该股票，继续处理其余股票。
- wheel 或共享检测器导入失败：策略注册失败并保留上一版有效注册表，不发布部分加载状态。
- 风险策略进入买入回测：后端拒绝并返回“风险策略不支持买入回测”。
- 部署健康检查失败：不切换生产容器，或立即回滚到上一镜像。

## 测试设计

### longbridge-stock 共享核心

- 每个新增或调整的检测器先写失败测试，再实现最小逻辑。
- 每种形态至少覆盖一个正例、一个近似但无效的反例和一个确认时间断言。
- 2B严格验证五浪、破低、下一根立即大阳收回；延迟收回不得命中。
- 孕线严格验证前一根小实体、后一根全区间吞没、方向、实体和量能。
- 右肩提前买点与颈线确认后的头肩底必须产生不同检测事件。
- 全量重放与逐根增量更新的结果一致。

### TickFlow 适配与注册

- 独立策略只启用自己的检测器。
- 局部K线索引正确映射到联合交易日日历。
- 买点映射为 entry；风险形态映射为 exit/risk。
- 风险策略可在筛选器命中，但回测接口拒绝执行。
- 所有新增内置策略声明资产类型、日线周期、矩阵执行后端和所需字段。
- 注册表无重复ID、无加载错误，现有19张内置策略和原组合策略行为不变。

### 产品与部署验收

- 后端全量测试通过，ruff检查通过。
- 前端测试和生产构建通过。
- Docker镜像构建成功，固定 wheel 在镜像内可导入。
- 部署后通过策略列表接口核对13张新增卡片及其角色。
- 在 `http://192.168.10.28:3018/screener?market=cn` 验证策略池名称、参数、风险标识和执行结果。
- 选取可控样本验证一张买点卡和一张风险卡；确认风险卡没有买入回测入口。

## 部署与回滚

使用唯一的新镜像标签构建和部署，保留当前生产镜像标签作为回滚点。部署只替换应用镜像，
不删除、不覆盖 `data/` 中的行情、用户设置、自定义策略、AI策略、认证信息和监控规则。

部署顺序：构建 wheel、运行核心测试、更新 TickFlow vendor 固定信息、运行 TickFlow 测试与
前端构建、构建镜像、启动候选容器、执行健康检查、切换生产、浏览器验收。任一关键检查
失败则停止切换或恢复上一镜像。

## 非目标

- 不实现笔记中尚无完整定义的另外九类买点。
- 不接入“道氏趋势线—买卖点”或“强弱结合”。
- 不新增做空交易、分钟周期或自动下单。
- 不删除现有“多市场结构突破”组合策略。
- 不调整与本功能无关的策略、数据源或用户配置。
