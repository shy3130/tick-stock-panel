# 手机端响应式适配（第一阶段）设计

## 背景

系统当前可以在手机浏览器打开，但全局布局固定为 `14rem` 侧栏加主内容区。在 390px 宽度下，侧栏占 224px，主内容区仅剩 166px，导致看板、操作栏和表格无法正常使用。

本阶段为现有 Web 系统增加可用的手机端布局，不改变后端接口、数据结构、路由或桌面端操作方式。

## 范围

本阶段覆盖：

- 全局导航与页面容器
- 市场看板
- 自选股
- 策略选股器
- 设置页

暂不单独重构回测、财务分析、行业分析等复杂页面。这些页面可通过手机抽屉访问，并保持现有基础滚动能力，后续按使用优先级继续适配。

## 响应式边界

- 小于 `768px`：手机布局。
- 大于等于 `768px`：保留现有桌面侧栏和页面布局。
- 支持的主要验收尺寸为 `390×844` 和 `430×932`。

## 全局导航

手机布局隐藏固定桌面侧栏，改为：

1. 页面顶部显示固定导航栏，包含菜单按钮、当前页面标题和 CN/HK/US 市场切换。
2. 点击菜单按钮后，从左侧打开抽屉。
3. 抽屉复用现有完整菜单，包含全部页面入口、数据源状态、实时行情状态、主题切换和设置入口。
4. 点击遮罩、关闭按钮、按 Escape 或切换路由后关闭抽屉。
5. 抽屉打开时禁止背景页面滚动，并提供可识别的对话框语义和焦点入口。

桌面端继续使用现有固定侧栏，不增加额外导航层级。

## 页面适配

### 市场看板

- 页面边距缩小为手机间距。
- 顶部状态和操作区允许换行，不得超出视口。
- 指数、宽度、成交额及热度卡片根据可读性切换为单列或双列。
- 图表和榜单保持完整数据，容器宽度不得撑大页面。

### 自选股

- 工具栏允许换行，常用操作保持可见。
- 卡片视图在手机上使用双列，窄内容自动截断。
- 表格视图放入横向滚动容器，不压缩列文本。
- 股票名称和核心行情应优先可见。

### 策略选股器

- 策略选择、市场选择和运行操作按纵向排列。
- 筛选条件区域允许折行和纵向滚动。
- 结果表格使用横向滚动，不改变结果数据与排序行为。

### 设置页

- 现有左侧竖向标签在手机端改为顶部横向滚动标签。
- 设置内容占满可用宽度。
- 多列表单在手机端改为单列，操作按钮保持可点击且不超出视口。

## 组件边界

- `Layout` 负责桌面侧栏、手机顶部栏、手机抽屉及抽屉开关状态。
- 导航内容提取为可复用的内部渲染单元，桌面侧栏和手机抽屉共享相同菜单数据，避免两套菜单失去同步。
- 页面组件只负责自身内容布局，不感知抽屉状态。
- 响应式规则优先使用现有 Tailwind 断点和工具类，不引入新的 UI 框架或全局状态库。

## 数据流与错误处理

响应式适配不新增网络请求。市场切换、实时行情状态、菜单偏好和页面数据继续使用现有查询与状态。

页面数据加载或请求失败时沿用现有提示。手机抽屉属于本地交互，不因数据请求失败而失效，确保用户始终可以离开当前页面或进入设置。

## 测试与验收

自动化测试覆盖：

- 手机导航标题与路由映射。
- 手机抽屉打开、关闭及路由切换关闭行为。
- 设置标签在手机布局下可横向访问。
- 新增的响应式辅助逻辑。

构建与回归验证：

- 前端单元测试全部通过。
- TypeScript 与生产构建通过。
- 后端测试保持通过，确认前端改动未影响部署组合。

真实浏览器验收在 `390×844` 和 `430×932` 下检查首页、自选股、选股器和设置页：

- 页面根节点不得产生非预期横向溢出。
- 主内容区占满手机宽度。
- 菜单可打开、关闭并完成路由跳转。
- 市场切换可操作。
- 表格横向滚动仅发生在表格容器内。
- 关键按钮的点击区域清晰可用。

同时在桌面视口复核现有侧栏、导航和主要页面布局没有回归。

## 非目标

- 不开发原生 iOS 或 Android 应用。
- 不在本阶段增加 PWA 安装、离线缓存或消息推送。
- 不改变行情刷新频率、策略逻辑或权限体系。
- 不重做视觉主题和桌面信息架构。
