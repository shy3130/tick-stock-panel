# 设置页修改访问密码设计

## 1. 目标与范围

为已登录用户提供可发现、可验证的访问密码修改入口。入口位于“设置”页的独立“账户安全”标签，避免与 TickFlow API Key、AI Key 或系统运行参数混在一起。

本次只补齐前端入口、表单交互和自动化测试。后端已有 `/api/auth/change-password` 接口及会话失效机制，前端 `api.authChangePassword` 也已封装，因此不修改认证存储与接口契约。

## 2. 页面结构

在设置页左侧标签列表新增“账户安全”，使用锁形图标。标签内容为一张“修改访问密码”设置卡，包含：

- 当前密码；
- 新密码；
- 确认新密码；
- 显示或隐藏三项密码的切换按钮；
- “修改密码”提交按钮；
- 表单内错误提示区域。

页面沿用现有设置面板的间距、颜色、输入框、按钮与错误状态样式，不新增全局样式或通用表单框架。

## 3. 交互与校验

提交前在浏览器执行以下校验：

1. 三项均不能为空；
2. 新密码至少 6 位；
3. 新密码与确认新密码必须一致；
4. 新密码不能与当前密码相同。

校验失败时不调用后端，错误显示在表单内，并保留用户已输入的内容以便修正。提交期间禁用按钮并显示处理中状态，防止重复请求。

提交调用现有 `api.authChangePassword(currentPassword, newPassword)`。后端返回的旧密码错误、会话过期、限流或其他错误均使用现有 API 错误消息显示在表单内。

## 4. 成功后的会话处理

后端修改密码后会清空所有现有会话，包括当前会话。前端收到成功响应后立即跳转到 `/login`，并通过登录页可读取的一次性导航状态显示“密码已修改，请使用新密码重新登录”。不在客户端保存或回填任何密码。

如果后端已经完成修改但跳转过程被中断，当前会话也已失效；下一次 API 请求会由现有全局 401 拦截器送回登录页。

## 5. 组件边界

- 新增独立的账户安全设置面板，负责表单状态、客户端校验、提交和成功跳转。
- `Settings.tsx` 只负责注册新标签，不承载密码业务逻辑。
- `Auth.tsx` 只增加对一次性成功提示的展示，不改变首次设密码和登录流程。
- 后端认证路由、密码哈希、会话存储和现有前端 API 封装保持不变。

## 6. 测试与验收

前端组件测试覆盖：

1. 设置页能看到“账户安全”标签并进入修改密码面板；
2. 密码少于 6 位时不提交并显示提示；
3. 两次新密码不一致时不提交并显示提示；
4. 新旧密码相同时不提交并显示提示；
5. 合法输入调用 `authChangePassword`，参数为当前密码和新密码；
6. 后端返回错误时在表单内显示原始错误消息；
7. 修改成功后跳转登录页并显示重新登录提示。

验收时运行相关前端测试、全量前端测试和生产构建，并在设置页手动确认暗色与亮色主题下的输入、错误、加载和成功跳转状态。
