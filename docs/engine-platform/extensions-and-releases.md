# 引擎扩展和更新

工作台的原有数据源插件、页面插件和后端扩展沿用现有的导入与升级方式。独立引擎扩展由「设置 → 导入与备份」导入，并在「已安装扩展」验证和启用。商业扩展还需要发行方签发的本机授权。[工作台使用说明](workbench-research-jobs.md)

## 导入后核对的状态

1. 预检时记录包 ID、版本、摘要、目标平台和所需能力。
2. 保存候选并启用后查看已安装状态和出错信息。商业包在「商业授权」绑定设备身份，再导入发行方凭证。
3. 从「引擎研究」预检一个小范围任务，核对实际提供的价格视图或数据来源。使用同一组输入核对升级和回退结果。

工作台宿主的许可与 Tivelo 组件许可见[许可说明](../../README.md#license)。安装器的 CLI 和可信公钥配置见 [Tivelo Extensions](../../packages/tivelo-extensions/README.md)。

## 安装和升级 Tivelo Pro

1. 向发行方取得与 TSP 后端的操作系统、架构和 Python ABI 匹配的 Tivelo Pro 签名 ZIP。普通策略回测需要 0.1.0a2 或更高版本。
2. 打开「设置 → 导入与备份 → 导入文件」，点击「选择文件」或拖入 ZIP。检查预览中的版本、平台和发行信息，点击「保存候选包」。
3. 在「已安装扩展」选中新版本，点击「验证并启用版本」。首次安装时，在「商业授权」点击「生成本机安装身份」，将页面显示的安装公钥交给发行方申请本机使用凭证。
4. 收到凭证后，在「商业授权」点「选择凭证文件」，选择 `.lic` 或 `.json`。也可拖入凭证文件，或展开「粘贴凭证 JSON」粘贴文件的完整内容。回到「回测 → 策略」即可[选择动态复权](workbench-research-jobs.md#动态复权扩展)。

升级前先确认现有凭证有效且覆盖目标版本。若旧凭证只覆盖旧版本，保留当前版本启用，向发行方申请同一安装身份下同时覆盖当前版本和目标版本的新凭证。在当前活动版本的「商业授权」导入并核验后，再验证并启用新版本。

ZIP 预览提示 `Unknown signing key for the requested purpose` 时，请核对发行方和包来源，并让部署者在 TSP 后端进程中设置 `TIVELO_RELEASE_TRUST_FILE`，指向包含经核实的发行公钥的信任文件。ZIP 的发行签名和本机使用凭证在不同步骤核验。

## 卸载 Tivelo Pro 动态复权

在「设置 → 导入与备份 → 已安装扩展」选择 `tivelo.pro.dynamic-adjustment`，点击「彻底卸载」并确认。卸载会移除这份扩展的所有已保存版本和程序缓存，立即生效。有使用该扩展的研究任务排队或运行时，等任务结束后再卸载。

安装身份和已导入的授权可用于重装。已生成的回测报告仍可查看。重跑锁定了此扩展的旧任务时，先重新导入并启用任务所用版本的 ZIP。

## 回退与旧任务重放

桌面程序可通过 `TSP --engine --report status.json status` 查看随包组合、当前组合、修订号和保留的组合。维护切换需要已认证的目标组合、当前修订号和空闲任务；恢复命令为 `TSP --engine --report restored.json restore --revision REVISION --to OLD_COMBINATION`。

已有报告可以继续读取。重放旧任务还依赖对应快照、策略定义和运行环境；版本或依赖不匹配时需要原来的组合。正式向用户分发独立引擎更新前，发行方需要配置可信公钥并完成目标平台的安装与回退验收。
