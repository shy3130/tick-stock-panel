# 引擎研究：使用和接入

在 TSP 普通「策略回测」页的「复权方式」中可选择前复权或后复权，默认前复权。回测结果记录所用口径，载入旧方案时缺省为前复权。日线仓位模拟在前复权时沿用复权价计算手数，在后复权时还原成交原价。启用并授权 Tivelo Pro 0.1.0a2 或更高版本后，可在同一表单选择[动态复权](#动态复权扩展)。

## 动态复权扩展

1. 在「设置 → 导入与备份」[安装、启用并授权](extensions-and-releases.md#安装和升级-tivelo-pro) Tivelo Pro 0.1.0a2 或更高版本。
2. 在「回测 → 策略」选择 A 股日线策略、日期和股票池，将「复权方式」切到「动态复权」。为建仓和清仓选择日线成交方式。
3. 点击当前表单的「运行回测」，在原页面查看净值、成交明细和所用口径。回测自动读取本地原始日 K 和除权因子，缺少必要行情或因子时在结果区提示。

策略决策使用按除权生效日重建的历史价格窗口，成交与费用使用原始日 K 价格，跨除权收益按因子衔接。普通动态复权使用工作台当前保存的历史数据。需要按历史可知时间锁定因子版本、复放公司行为时，走下文的[归档研究流程](#使用现有归档切换价格口径)。

## 用本地日K生成快照并回测

1. 打开「引擎研究」并点击「生成日K快照」。搜索并添加 A 股标的，选择开始和结束日期，再点击「生成快照」。两个边界日期均包含在快照里。若要预留指标预热期，可以把快照的开始日期选早一些。
2. 快照发布后，在任务详情中点击「用此快照回测」。选择工作区里已有的日线策略，需要时可在快照范围内缩短回测区间，然后点击「运行回测」。
3. 在回测页查看净值和交易明细。回测结果的版本记录包含快照标识，返回引擎研究可再次使用这份快照。

快照保存原始日K和所选标的的累计复权因子。回测使用快照结束日作为前复权锚点，预热和成交均在快照范围内。策略定义、标的资料、财务数据及基准取自当前工作区。所用的市场环境和扩展时序字段由正式回测另存过滤版本，可在重跑时复用。这类快照的可知时间按采集时点重建。

归档研究任务可选择匹配的 Tivelo 回测归档与快照，也可导入 JSON 准备计划。

## 使用现有归档切换价格口径

1. 将完整的 Tivelo 回测归档和对应快照分别放到当前数据目录的 `research/engine/inputs/` 下。每份输入使用独立目录，不要覆盖运行中的输入。
2. 打开「引擎研究」，新建任务，选择回测归档与匹配的数据快照。支持价格切换的严格日线归档会出现「更换价格口径」。
3. 选择不复权、前复权、后复权或已授权的动态复权。选择前复权或后复权时，填写快照使用的累计因子定义、因子基准和固定 UTC 锚点。选择动态复权时，填写因子定义与基准，由扩展按每个决策时间使用当时可见的因子。
4. 按页面要求确认策略口径，点击「另存回测输入」，检查后提交。新任务使用另存的输入，原归档仍可使用。

可参考[旧 TSP 日线导入](../../packages/tivelo-data/README.md#从既有-tsp-日线仓库导入)、[从旧除权事件重建因子](../../packages/tivelo-data/README.md#从旧除权事件重建免费前后复权)和[兼容日线回测接口](../../packages/tivelo-backtest/README.md#从快照读取兼容回测的日线)。只有来源确实提供历史版本和可知时间时，才能作为严格历史回测的依据。

## 查看进度和导出结果

1. 在「新建任务」准备输入后，点「检查输入与预算」。核对归档、快照、价格口径和预算，再点「提交研究任务」。输入发生变化时需重新检查。
2. 在「最近任务」选择任务，查看其状态和「执行阶段」。有多个步骤时，用「研究步骤」选择所需的节点。采集步骤发布后可查看快照标识、路径和覆盖范围。
3. 回测步骤发布报告后，可在「研究报告」区查看结果。「导出报告 JSON」保存报告。「导出结果 ZIP」同时保存报告、输出清单和校验过的执行文件。
4. 若浏览器暂时读不到报告，使用「重新读取报告」。进度走完后，仍需等报告生成并通过校验。

### 取消、重试与权限

- 任务正在排队或执行时，可点「取消任务」。页面会等待执行进程退出，已发布结果会保留。
- 任务失败、取消或中断后，可检查任务错误、执行阶段和尝试记录，再使用「按原输入重试」。如已耗尽尝试次数、需要重新采集行情或希望修改输入，用「复制为新任务」重新检查并提交。
- 遇到权限提示，检查工作台登录状态。若提示服务不可用，在服务恢复后回到任务列表刷新。

## 分别选择日线和除权因子来源

「设置 → 数据源」里的日 K 和除权因子是两项独立能力。研究计划可分别包含 `tsp_daily` 与 `tsp_factors` 采集步骤，从对应的实际路由获取日线和单次除权事件。按本机 `GET /api/engine-jobs/schema` 填写计划中的来源和预期 Provider，并查看预检与任务报告。路由变化后，核对计划锁定的来源再重新预检。数据集的可用范围、因子单位和可知时间需分别检查。[数据与市场契约](data-and-market-contracts.md)

## 按交易日派发

「引擎研究」的「触发计划」可将已经检查过的任务模板按交易日、UTC 固定间隔或数据版本发布派发。普通策略回测直接按所用行情的日期回放。

选择「交易日」触发时，填写交易所、已安装日历版本、日期区间、开盘或收盘基准及偏移分钟。先保存为暂停计划，在「查看派发日历」检查实际日期和时间，再启用。按 API 创建时，用 `GET /api/engine-jobs/schedules/schema` 获取结构，`GET /api/engine-jobs/schedules/calendar-presets` 查询可选版本，`POST /api/engine-jobs/schedules` 提交。

## AI 或其他客户端接入

使用工作台登录会话调用 `GET /api/engine-jobs/schema` 获取请求结构。先用 `POST /api/engine-jobs/preview` 预检，再用 `POST /api/engine-jobs?expected_plan_id=<预检返回的 plan_id>` 提交已检查的输入。接口输入以当前服务返回的 schema 为准。

| 操作 | 接口 |
| :--- | :--- |
| 查看状态和执行阶段 | `GET /api/engine-jobs/{job_id}` |
| 读取已发布的研究报告 | `GET /api/engine-jobs/{job_id}/reports/{node_id}` |
| 下载结果 ZIP | `GET /api/engine-jobs/{job_id}/results/{node_id}.zip` |
| 取消或按原输入重试 | `POST /api/engine-jobs/{job_id}/cancel` 或 `POST /api/engine-jobs/{job_id}/retry` |

`node_id` 对应工作台所选的研究步骤 ID。`GET /api/engine-jobs/price-views` 返回价格视图及安装状态，`POST /api/engine-jobs/inputs/price-variants` 为已有归档生成新的价格口径输入。

TSP 原有数据源插件继续使用既有 `plugin.yaml` 和 Provider 接口，接入说明见[数据源插件开发](../plugin-development.md)。独立数据引擎的来源接入见 [Tivelo Data](../../packages/tivelo-data/README.md)。

## 逐笔策略回测

逐笔回测通过研究计划导入已准备好的策略和历史事实。具体数据要求及独立引擎接口见[从策略归档运行逐笔回测](../../packages/tivelo-backtest/README.md#从策略归档运行逐笔回测)。真实来源的完整性应单独核对。

与外部 AI 集成时，先区分普通策略回测的 Tier A 接口与工作台的研究管理接口。[AI 接入指南](../ai-integration.md)
