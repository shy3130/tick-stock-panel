# Sycee 专属能力

本文只记录 Sycee 相对上游 `tickflow-stock-panel` 新增或独立维护的产品能力。行情、指标、选股、回测、监控和财务分析等上游基础能力继续以原项目文档为准。

## 已实现

### 个性化每日简报

每日简报按需聚合市场概览、最新市场复盘、当前持仓、自选股、监控提醒、策略跟踪和研究账本,提供晨报与晚报两个视角。晨报读取近 24 小时提醒,晚报只读取当日提醒;两者都只保留当前持仓或自选股相关事件,并汇总:

- 市场情绪、涨跌家数、涨跌停与领先方向
- 持仓市值、浮动盈亏、当日涨跌和行情新鲜度
- 需要处理的持仓/自选提醒
- 尚未对齐最新交易日的策略快照
- 待整理或跟踪中的下一项研究动作

简报可导出 Markdown。页面只通过公开 HTTP API 读取现有数据,不复制行情、提醒或用户业务数据,也不宣称自动定时推送能力。任一数据源暂时不可用时,其他段落仍可生成并明确标出缺失项。

### 策略横向对比

策略对比工作台复用上游公开策略清单和流式回测 API,在相同股票池、日期区间、初始资金与交易成本下顺序运行 2 至 5 个策略。结果并排展示总收益、年化收益、夏普比率、最大回撤、胜率、交易次数和归一化净值曲线,并可导出 CSV。

对比任务按策略逐个执行,避免同时运行多组回测放大内存压力。该功能只消费上游公开输出,不导入或修改策略引擎、回测引擎和数据存储内部实现。

### 持仓管理

持仓管理以独立交易流水为数据源,支持记录、编辑和删除买入/卖出交易。系统按交易日期顺序重算:

- 当前持仓数量、移动加权平均成本和持仓成本
- 使用已有行情 API 得到的当前市值、浮动盈亏与收益率
- 卖出交易形成的已实现盈亏
- 买卖费用对成本和已实现盈亏的影响

行情存在盘中实时蜡烛时明确标记为“实盘”;否则展示最近收盘日期。部分持仓缺少行情时,组合摘要会显示待补价数量,不会把缺失价格当作零。

数据按登录用户隔离,保存位置为:

```text
data/users/<user-id>/sycee/portfolio.json
```

每次新增、编辑或删除交易都会重新验证完整历史。若操作会造成任一历史时点卖出数量超过可用持仓,系统拒绝写入并保留原数据。写入采用临时文件加原子替换。

持仓页还可为一个包含卖出信号的策略启用“持仓卖出提醒”。Sycee 单独保存所选策略、推送渠道和托管规则 ID,再通过上游公开的监控规则 API 幂等同步规则:

- 规则作用域始终是当前持仓代码,不会扫描或推送非持仓股票。
- 通知事件固定为 `sell_signal`,不会混入买入、进入选股池或移出选股池事件。
- 清仓后删除托管规则但保留配置,再次录入持仓时自动恢复。
- 只更新随机生成的 Sycee 托管规则 ID,不修改用户手工创建的监控规则。
- 应用内告警、SSE 和所选飞书/企业微信推送均复用上游现有通知链路。

提醒配置按登录用户隔离,保存位置为:

```text
data/users/<user-id>/sycee/portfolio_sell_alert.json
```

Sycee 后端不导入策略或监控内部模块;期望规则由 Sycee API 输出,前端仅通过公开 `/api/monitor-rules` 接口完成同步。

### 交易日志与复盘归因

持仓页为每笔交易提供独立的计划和复盘记录,可填写关联策略、入场逻辑、预期路径、失效条件、退出依据、复盘结论与错误标签。复盘列表支持按策略、错误标签和实际盈亏结果筛选。

卖出交易的归因直接从 Sycee 交易流水重放得到:

- 盈亏沿用持仓管理的移动加权成本口径,买入费用进入成本,卖出费用从收益中扣除。
- 收益率以该笔卖出分摊的移动成本为分母。
- 持有周期按本轮首次建仓到卖出日的自然日计算;完全清仓后重新建仓会重置。
- 原交易被编辑后,成本、盈亏、收益率和持有周期实时重算,不会把旧结果固化进复盘文件。
- 原交易被删除后,用户填写的复盘保留为孤立记录,由用户确认后再单独删除。

复盘数据只引用稳定的交易 ID,按登录用户隔离并保存到:

```text
data/users/<user-id>/sycee/trade_reviews.json
```

该功能只依赖 Sycee 持仓 API 的公开结果,不读取或修改上游策略、回测、行情与存储内部实现。

### 用户数据备份

数据备份页按当前登录用户导出版本化 JSON 快照,范围只包含 Sycee 自有的持仓流水、持仓卖出提醒配置、交易复盘、研究账本和策略跟踪。快照不包含账户、邀请码、登录会话、行情或上游配置,单个文件上限为 20 MB。旧版 version 1 快照未包含策略跟踪字段时,恢复会保留当前策略跟踪数据。

恢复前会完整校验五部分数据及持仓交易顺序;校验失败不会修改现有文件。恢复开始前,服务端会把当前文件复制到当前用户目录下的:

```text
data/users/<user-id>/sycee/backups/<restore-id>/
```

恢复使用临时文件和原子替换;任一文件写入失败时会尝试把全部 Sycee 数据回滚到恢复前状态。该功能只注册在 Sycee Router 和前端注册表中,不新增上游接入点。

### 策略生命周期与模拟跟踪

策略跟踪页保存按用户隔离的跟踪计划,每项计划引用公开策略 ID,记录创建时的策略参数与覆盖配置,并固定股票池、起始日、初始资金、持仓上限和交易成本。计划可在跟踪、暂停和结束三种状态间推进,并保留可编辑备注。

更新快照时,前端通过上游公开的流式策略回测 API 按计划参数运行到当日,只把累计收益、年化、夏普、最大回撤、胜率、交易数和期末权益写入 Sycee 文件。同一截止日再次运行会替换当天快照,避免重复记录。暂停或结束的计划不能写入新快照。

```text
data/users/<user-id>/sycee/strategy_tracking.json
```

Sycee 后端不导入策略、回测、行情或存储内部模块;计划中的策略 ID 失效后,历史快照仍会保留,但不能继续运行。

### 研究账本

研究账本用于保存可回看的判断过程,而不是生成荐股结论。每条记录包含:

- 研究对象:个股、策略、板块或市场
- 核心假设
- 支持证据与反方证据
- 判断失效条件
- 下一项验证或跟踪动作
- 草稿、跟踪、验证、失效和归档状态
- 自定义标签与更新时间

个股研究不必从空白表单开始。打开任一个股预览后点击 **加入研究**,系统会:

- 首次捕获时建立一条“待整理”记录。
- 自动保存标的、入口来源和可用的监控触发快照。
- 将后续不同来源追加到独立的“系统捕获记录”时间线。
- 对相同来源去重,避免重复点击产生重复记录。
- 在结果提示中提供“查看记录”和“撤销”;撤销不会删除已经手动编辑的研究内容。

自动捕获只负责建立研究线索,不会把机器生成内容混入支持证据或反方证据。用户可随后补充核心假设、失效条件和下一步,并把状态从“待整理”推进为跟踪、验证、失效或归档。

数据按登录用户隔离,保存位置为:

```text
data/users/<user-id>/sycee/research_ledger.json
```

写入采用临时文件加原子替换,避免进程中断留下半写文件。

### 私有访问与多用户

Sycee 提供公开品牌入口、邀请码注册和独立账户。用户内容通过请求级用户上下文解析到各自目录;行情数据、基础指标和公共计算仍由所有用户共享,避免复制上游数据层。

### 产品工作台

Sycee 独立维护品牌、公开首页、产品化导航、响应式应用外壳和服务器部署体验。这些内容不改变上游策略与行情接口。

## 代码边界

Sycee 功能优先放在以下目录:

```text
backend/app/sycee/
frontend/src/features/sycee/
backend/tests/test_sycee_*.py
```

项目只保留以下一次性公共接入点:

| 接入点 | 作用 | 冲突风险 |
| :--- | :--- | :--- |
| `backend/app/main.py` | 挂载统一 `sycee_router` | 稳定网关,避免继续扩大 |
| `frontend/src/router.tsx` | 展开 `SYCEE_ROUTES` | 稳定网关,新增路由不再修改 |
| `frontend/src/lib/navRegistry.ts` | 展开 `SYCEE_NAV_ITEMS` | 稳定网关,新增导航不再修改 |
| `frontend/src/lib/api.ts` | 导出公共 `request` 请求函数 | 低,不增加业务方法 |
| `frontend/src/features/sycee/registry.tsx` | 注册全部 Sycee 路由和导航 | Sycee 自有,允许扩展 |

后续 Sycee API 应继续挂在统一 Router 内。前端页面和导航只在 Sycee 注册表增加,业务类型和请求方法保留在对应 feature 目录。上述公共网关保持稳定;只有确实需要改善用户工作流时,才允许增加薄适配层。

## 最小影响规则

自研功能默认隔离,必要的原版接入必须满足:

- 业务代码只进入 `backend/app/sycee/` 和 `frontend/src/features/sycee/`。
- 原版文件只允许保留按钮、插槽、注册或上下文传递,不得承载 Sycee 业务逻辑。
- 优先修改一个共享入口,不得在多个页面复制相同接入代码。
- 不修改原版数据文件和 schema;只通过稳定 ID 引用原版实体。
- 不复制原版模块形成平行实现。
- 只能消费原版已有的公共 API 和服务边界。
- 策略、回测、指标、行情和存储内部仍禁止直接侵入。
- 每个被触碰的原版文件都必须登记在 [sycee-integrations.json](./sycee-integrations.json),说明接入原因。
- 若功能需要把业务逻辑写进原版核心才能实现,该方案直接否决并重新设计。

`backend/tests/test_sycee_extension_boundary.py` 会检查固定网关、直接导入和接入清单,阻止未登记的 Sycee 代码渗入原版模块。该规则约束的是新增 Sycee 功能;纯上游同步提交不受此 changed-file 限制。

## 上游升级原则

1. 上游同步与 Sycee 功能开发使用独立提交或 PR。
2. 不复制行情仓库、策略引擎或回测引擎;通过现有接口复用。
3. 用户数据使用独立文件或独立 schema,只保存对上游实体的 ID 引用。
4. 合并上游后同时运行上游测试与 `test_sycee_*` 测试。
5. 上游升级继续保留 merge commit,具体流程见 [upstream-sync.md](./upstream-sync.md)。
6. 新增 Sycee 功能完成前必须通过扩展边界测试。
