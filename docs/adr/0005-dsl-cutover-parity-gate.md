# 0005 — DSL 切换的 parity 对拍闸门

- **状态**：已接受（2026-07-02）
- **相关**：策略 DSL 设计 Part A、决策 D4（彻底切换删 Python）、D6（不做存量迁移工具）

## 背景

D4 决定彻底切换到 DSL 并删除 `importlib`/`exec` 执行路径；D6 决定不做"存量 AI Python 策略自动转 DSL"的转换器。18 个内置策略改为手写 DSL 定义。

风险：删除 Python 执行后即失去旧路径做对照。若 DSL 版内置策略因 null 处理 / 边界 / 评分归一化细节与旧 Python 版选股结果不同，用户策略会**静默变脸**且无法回滚验证。

D6 的"不考虑存量工具"本意是**不做自动迁移转换器**，与"是否做正确性验证"是两回事——不能因 D6 而放弃切换前的正确性验证。

## 决策

删除 Python exec **之前**，设一次性 **parity 对拍闸门**：
- 对 18 个内置策略，旧 Python 版 vs 新 DSL 版，在**同一段历史 enriched 面板 + 同一区间**上运行；
- 断言：**选出的 symbol 集合一致** 且 **score 在浮点容差内一致**；
- 18 个全部通过，才允许删除 `importlib` / `exec_module` / `ai_generator` 的 Python 生成路径。

该对拍用"即将删除的 Python 路径"作 oracle，属**验证脚手架（用完即弃）**，不是迁移转换器，不违 D6。

## 后果

- ✅ 为不可逆的删除动作设了客观验收标准，杜绝内置策略静默变脸。
- ✅ 顺带成为 IR compiler 黄金测试（ADR-0001 后果项）的第一批真实用例。
- ⚠️ 需在删除前保留一个能同时跑旧 Python 与新 DSL 的临时环境（短暂并存），仅用于对拍。
- ⚠️ 对拍只覆盖 18 内置；用户存量 AI Python 策略不在闸门内（按 D6，由用户用 AI-to-DSL 重生成）。
